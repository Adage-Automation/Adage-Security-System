# User Guide — Admin

Covers everything in the [Security](./user-guide-security.md) and [HR](./user-guide-hr.md) guides, plus the screens only Admin can reach: Users, Audit Log, and Settings. (Employees is shared with HR, and Missing Movements is shared with Security too — not Admin-only; see the [HR guide](./user-guide-hr.md) or [Security guide](./user-guide-security.md#adding-a-movement-someone-forgot-to-tap-missing-movements) if that's what you're looking for.)

## Employee management

Navigate to **Employees** (also available to HR, not Admin-only).

- **Add employee**: fill in Employee Code (must be unique) and Name; Email and Car Number are optional — leave either blank if you don't have it yet, and use **Edit** on the same screen once you do. The email you enter is where their movement-record emails will be sent — double check it. An employee with no email on file simply can't be sent EMAIL DETAILS until one is added (shown clearly on their details page). Employee Code/Name/Email/Car Number are all trimmed automatically, so a stray leading/trailing space from a copy-paste won't create a confusing duplicate.
- **Adding several joiners at once**: click **Download Import Template** for a blank spreadsheet with the right columns (an "Instructions" tab explains the format and shows an example row — don't add that example row to the real data). Fill in one row per new employee, save the file, then click **Import from Excel** and pick it. You'll get a result summary — "N added, M skipped" — with a reason next to every skipped row (a missing field, a bad email, a code that's already taken); only the bad rows need fixing and re-uploading, not the whole file.
- **Search**: the list is the full employee roster (200+ people), so use the search box (matches name, code, email, or car number) rather than scrolling — results load a page at a time with a **Load More** button. After loading several pages, a floating **Back to top** button appears once you've scrolled down a bit, for getting back to the search bar without a long manual scroll.
- **Sortable columns**: click any column header (Code, Name, Email, Car Number, Team, Status) to sort by it, click again to reverse. Sorting always considers the full roster, not just whatever page you've loaded so far — e.g. sorting by Status pulls in every not-yet-loaded page first, so deactivated employees reliably surface at the top rather than being hidden on a page you hadn't reached yet.
- **Export to Excel**: downloads a `.xlsx` of the full roster (active and inactive, with status shown) as it stands right now. Useful for archiving or sharing. This is a one-way snapshot, not a live-synced file — edits made here afterward won't retroactively change a file you already downloaded. It's a different file from the import template above: every row in an export is an *existing* employee, so re-uploading it via Import would just report all of them as skipped (already exists) — for adding new joiners, start from **Download Import Template** instead.
- **Edit**: update an employee's name, optional email, optional car number, or Team without changing the employee code. Blanking the Email or Car Number field and saving actually clears it (fixed 2026-10-05 — it used to silently leave the old value in place).
- **Team**: pick from a fixed dropdown list of your organization's teams/departments (Add/Edit forms and the bulk-import Team column). **Required when adding a new employee** — needed for the team-wise breakdown on the Insights screen (below). The Edit form still allows leaving it as "Not set" for an existing employee whose team wasn't captured when they were added.
- **Deactivate**: marks an employee inactive instead of deleting them. They stop appearing in the Security search box, but every historical movement record stays fully intact and visible on the Dashboard. Use this when someone leaves the company — never delete an employee outright.
- **Reactivate**: brings a deactivated employee back into the Security search box.

Deactivated employees still appear on Missing Movements (see below), since you may need to add a movement for someone who has since left.

## Insights (HR/Admin only)

Navigate to **Insights** (also available to HR, not Admin-only; Security never sees this tab).

A read-only reporting dashboard built from the same guard-recorded movement data as the Dashboard — nothing here is editable, and nothing you do on this screen can change any recorded entry/exit.

- **Date range**: pick with the quick presets (Today, Yesterday, This Week, This Month, All Time, or Attendance Month — the latter follows a 26th-to-25th cycle with prev/next arrows to step between cycles) or set From/To directly.
- **Filters**: Team, Unit (Security 1 / Security 2, or however many security accounts exist), Movement type, a Days scope (Without weekends / With weekends / Just weekends), and the Employee search box all live behind the **Filters** button, collapsed by default to keep the bar compact — click it to expand them in place. The button shows a badge with how many of these are currently set, so you can tell at a glance whether anything's active without opening it. **Clear** resets Team/Unit/Movement/Days and the selected Employee back to defaults (it doesn't touch the date range, which has its own clear/reset).
- **Reference window, not a rule**: the office uses flexible timing, so the shown shift reference (e.g. 09:30–18:30) is informational only — it is never used to flag anyone as "late." The one real number tracked is **hours shortfall**: did the employee's first-entry-to-last-exit span that day reach the expected daily hours (configurable in **Settings** → Expected Daily Hours).
- **What's shown**: Avg Duration, Short & Long-Duration Days; Hourly Entry & Exit Distribution; a collapsible **Department Comparison** section (median duration, short/overtime rate per team, collapsed by default — click **Show charts** to expand); and a team-wise breakdown (detail table). Every chart's y-axis is labeled with what it counts (Hours, Employees, Movements, % of roster, etc.). (Daily Entries/Exits/Present, Daily Attendance Rate, Missing Movements Trend, and Unit Activity charts were hidden 2026-10-13, by request — not removed, just not currently shown.)
- **Click a bar/point for details**: every chart here is clickable — click one to see exactly who's behind that number (e.g. click "Production" in Team Breakdown to see every employee on that team; click a shortfall bar to see who fell short that day).
- **Per-Employee Detail**: search for any one employee to see their own trend — average arrival/departure time, a daily-duration chart (with the expected-hours line shown for reference), and daily entry/exit counts, all for the date range selected above. Search includes deactivated/former employees too (marked "· inactive"), e.g. to review someone's attendance pattern after they've left. Added 2026-10-27.
- **"Days Present" vs. "Days With Hours Tracked"**: these sound similar but aren't the same. "Days Present" (Team Breakdown table) is a *team total* — every employee's tap-in days added together over the range (any tap counts, even without a matching exit), not a day count or headcount; 10 people averaging 20 attended days each over the range shows 200. "Days With Hours Tracked" only counts days with both an entry *and* an exit, since that's what's needed to calculate a real duration — Team Breakdown's Avg Duration and Short-Duration % are both rated against this, not against "Days Present", so a team with a lot of missing exits doesn't get an artificially low shortfall rate.
- **Export to Excel** is available on Team Breakdown, the Daily Roster modal, and every drill-down modal (the exact rows on screen, not a separate report).

## User management

Navigate to **Users**.

- **Add user**: Name, Email, Username, temporary Password, and Role (SECURITY / HR / ADMIN). The role determines what they can access: Security gets the recording workflow plus Dashboard plus Missing Movements; HR gets Dashboard plus Employees (no recording — HR lands on the Dashboard after login, not the recording screen); only Admin additionally gets Users, Audit Log, and Settings. Choose carefully — it's not just a label.
- **Search**: filters the list by name, username, email, or role as you type.
- **Edit**: change a user's name, email, or role after the fact — e.g. fixing a mistyped email or reassigning someone to a different role. Changing your own role away from Admin warns you first (same as disabling your own account below) — it immediately removes your own access to Users, Settings, and the Audit Log.
- **Security units**: each security unit (gate/location) has one shared login account used by all guards at that unit — not one account per guard. That account's **Email** field is the unit's own address (e.g. `securityunit1@adage-automation.com`) and is used to both **send** and **CC** the account automatically whenever anyone logged into it sends "Email Details" — nothing to configure separately. The same applies to HR/Admin accounts, sending from and CC'ing their own login email too. Adding a new unit is just adding another shared account the same way — the new mailbox also needs adding to the Exchange access-policy scope group before its emails can actually send "as" it (until then, sends from that account fall back to a fixed address automatically, so nothing breaks — it just won't show the unit's own address as sender yet).
- **Disable / Enable**: disabling a user immediately blocks login (even an existing open session is re-checked on the next request and will be logged out) — use this rather than deleting a user (there is no delete), since audit history and past movement records reference them permanently.
- **Reset password**: sets a new password for a user directly — they are not notified, so share the new password with them yourself. Use this for a locked-out user who can't complete the self-service flow below. Users can also use the self-service **Forgot password?** link on the login screen; it sends a single-use reset link to the registered email address.

## Settings

Navigate to **Settings**. These values are used throughout the system instead of anything being hard-coded:

- **Company Name** — appears on generated reports.
- **Timezone** — should stay `Asia/Kolkata` unless the company's operating region changes; movement timestamps are computed against this. Must be a real IANA timezone name (e.g. `Asia/Kolkata`, not a typo like `Asia/Kolkota`) — checked against the browser's own list of valid zones before saving. Changing it asks you to confirm first, since it affects how every movement timestamp is computed and displayed from that point on.
- **Email Sender Name** — the display name shown next to the sender's address on outgoing emails (not the address itself — that's whichever account sent it, see below).
- **Shift Reference Start / End** and **Expected Daily Hours** — back the Insights screen's hours-shortfall metric. The start/end times are shown only as a reference window on charts (flexible timing means they're never a "late" cutoff); Expected Daily Hours is the one number actually compared against each employee's completed hours.

Edit as many fields as you need, then click **Save all changes** once — it's greyed out until something's actually changed, and shows an "Unsaved changes" note while you're mid-edit so you don't lose track of what you've touched. Only the fields you actually changed are saved.

There's no security-email setting here — with multiple security units (each its own shared login account on the Users screen), an emailed report is automatically sent from and CC'd to whichever account sent it. Nothing to configure per send.

## Missing Movements (Security/Admin)

Navigate to **Missing Movements** (also available to Security, not Admin-only, as of 2026-10-26 — see the [Security guide](./user-guide-security.md#adding-a-movement-someone-forgot-to-tap-missing-movements)). Guards sometimes forget to tap ENTRY or EXIT entirely — this screen is where that gets fixed. Requires the `CORRECT_RECORDS` permission (Security and Admin by default; not HR).

**Important: this only fills in a genuine gap — it never changes a record that already exists.** A record with a real recorded time (even a wrong one — guard tapped EXIT when they meant ENTRY, say) can no longer be edited at all, as of 2026-10-23. This screen used to be called "Corrections" and let an admin change an existing record's type/time; that capability is gone — only a movement the employee is genuinely missing for that day — no ENTRY, no EXIT, or neither — can be added. (If a guard really did tap the wrong button, there's deliberately no in-app way to undo that anymore — talk to whoever manages the system if that comes up.)

The date defaults to **Yesterday**, not Today — while a shift is still in progress, "missing EXIT" usually just means they haven't left yet, not a real gap; Yesterday is settled, so everyone on that list genuinely needs fixing. Pick any date directly with the calendar field, or tap **Attendance Month** (prev/next arrows to step between 26th-to-25th cycles, same as Insights' own Attendance Month filter) to see every gap across the whole cycle in one list — tap it again (now labeled **Exit Attendance Month**) to go back to the plain daily view. While it's on, the date field itself is replaced by the cycle's own dates (e.g. "26 Sep – 25 Oct 2026") instead of sitting there next to them showing some unrelated single day — only one date on screen at a time, never two conflicting ones. A "missing EXIT" for **today** specifically is left off the list entirely until the day is actually over — a note explains this whenever the current view reaches today. An orphan EXIT with no matching ENTRY is a genuine anomaly regardless of the time of day, so that can still show up for today even though "missing EXIT" won't.

Pick a date and you'll immediately see **who's missing an ENTRY or EXIT that day** — a clickable list, so there's no need to search employees one at a time to find who actually needs fixing. Each employee appears once, with every day of theirs that's missing something shown as its own small button (e.g. "Add Missing Exit") — in Attendance Month view someone missing 5 days in the cycle shows as one row with 5 buttons together, rather than scattered across 5 separate rows. Each button does exactly one thing when tapped — jumps straight to the Add form for that person and day — with no separate click zone for anything else, so there's nothing to miss-tap on a phone. The list's column headers stay pinned while you scroll through a long Attendance Month list. It looks at how the day actually started and ended, not just whether each type showed up at all — someone whose day ends on an ENTRY (stepped out and back in, then never tapped the final exit) still shows up here, even if an EXIT is technically on record somewhere earlier that day; a repeated tap of the same type (two ENTRYs at the same minute — a known offline-sync/double-tap pattern) is treated as noise, not a second real session, so it never creates a false gap on its own. Someone with zero taps at all isn't shown here (that's leave/holiday/remote work/a missed day entirely, not a one-sided gap). Saving an add takes you right back to the list at the same scroll position, so working through several people in a row doesn't keep bouncing you back to the top. To review someone's day before adding anything, use the search box above instead (still includes inactive/deactivated employees, so you can add a movement for someone who has since left) — once selected, a "Records on {date}" heading above their table confirms exactly which day you're looking at. Searching for someone while **Attendance Month** is active shows their every missing day across the whole cycle instead of one pinned date — there's no single day to show a table for in a multi-day cycle, so it's the same button-per-day shape the list itself uses, scoped to just that one employee. Adding one of their days from this scoped view keeps you on that same employee afterward — their remaining missing days shrink in place — rather than bouncing you back out to the full list, which would undo the point of having searched for just them.

Once an employee is selected, their movements for that day appear in a table. Below it, an **Add Missing ENTRY**/**Add Missing EXIT**/**Add Missing Record** button appears only when something is actually missing for that day — labeled for whichever one it is, or generic when both are missing; if the day is already genuinely closed out (the same first/last-movement logic as the list above, not just "one of each type exists"), no button shows at all, since there's nothing left to add. You'll be asked for the time and an optional **reason** (made optional 2026-10-26, by request) — whatever reason you do add is stored in the audit log alongside the addition (fixed 2026-10-23 — this previously only landed on the record itself, not the Audit Log screen). The form's submit button says **Add** (not "Save") — the one inconsistent word on an otherwise all-"Add" page, fixed 2026-10-26.

**The time has to actually close the gap, not just be the right type** (fixed 2026-10-28) — a missing EXIT has to be after everything already recorded that day, a missing ENTRY has to be before everything already recorded. A hint under the time field shows that boundary before you save; typing something that wouldn't actually fix the day gets rejected with a message stating the exact time it needed instead, rather than quietly adding a record that leaves the day still broken.

Typing a name/code in the search box that matches nobody now says **"No matches found"**, instead of the dropdown just staying blank with no feedback either way.

## Audit log

Every login/logout, every ENTRY/EXIT, every correction, every employee/user change, every settings change, and every email attempt (sent or failed) is recorded in the audit log with who did it and when. Navigate to **Audit Log** to browse it — filter by entity type, by who performed the action, or by a date range, and search by keyword across the action, entity, user, and IP address to narrow down an investigation. Results are always shown newest-first; use **Load More** to page through older history. Nothing is ever silently lost.

**Export to Excel** pulls out whatever the current filters show (up to 5,000 rows, newest first) as a spreadsheet — useful for pulling matching rows out for a compliance or HR record during an investigation, instead of scrolling and transcribing by hand. Added 2026-10-27, matching the same Export every other table in the app already has.

## Things that are intentionally not built

- **No working-hours timesheet roll-up** — the day view shows a total (first entry to last exit) as a convenience, but there is no daily/weekly timesheet, no per-gap breakdown, and no payroll export. The system is a movement register, not a timesheet.
- **No automatic or scheduled emails** — every email requires someone to explicitly click EMAIL DETAILS.
- **No keyboard shortcuts** for ENTRY/EXIT or any other state-changing action, anywhere in the app — this is deliberate, to prevent an accidental keypress from recording the wrong thing.
